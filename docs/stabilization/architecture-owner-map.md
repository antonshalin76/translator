# Translator stabilization SRP owner map

Baseline: `9291e8beafee3e02aaa179178ce460ac9e6c6de2`.

This is the Stage A working copy. It is not architect-approved until the final
verdict identifies and approves the same frozen candidate tree.

Architectural boundary remains three processes: Rust daemon owns control and the audio graph; Python sidecar owns inference/provider sessions; Tauri owns only the local authenticated proxy and views. No database, broker, outbox, scheduler, or extra orchestrator is introduced.

```text
Tauri views -> generated DaemonClient -> HTTP adapter -> ControlApplication
                                                -> RuntimeSupervisor
                                                   |- DirectionWorker x2
                                                   |- topology/routing/mix adapters
                                                   `- gRPC -> ProviderRegistry -> Provider session
ControlApplication/RuntimeSupervisor -> RuntimeProjection -> SSE/Tauri views
```

## Structural rules

- `RuntimeStore` cannot independently mutate lifecycle, consent, readiness, route selection, or effective controls; it receives committed owner snapshots.
- HTTP, gRPC, and Tauri are adapters. They validate/serialize but do not own domain transitions, retries, or optimistic effective state.
- Runtime policy is defined once in Rust core and projected as resolved typed values. Release/eval policy remains a separate versioned contract.
- Provider fakes live in tests. Production keeps one execution interface; obsolete fallback/runtime copies are deleted in the same stage that replaces them.
- Domain owners emit typed content-free events directly to `tracing`/projection. No custom event broker is added.
- The standalone validation runner admits each gate only while it is the sole Linux task, has no direct child, and retains default `SIGCHLD`; after admission it owns the gate process group and every newly adopted descendant. Live polling uses exact-PID nonblocking reap, excludes only the direct gate child, and leaves signalling policy in the termination owner. Real lifecycle tests execute one method per clean worker behind a clean supervisor so the shared test host never becomes the subreaper. The supervisor normalizes `SIGTERM`, arms Linux parent-death signalling before worker spawn, and routes outer-parent death through the same tree cleanup; watchdog cleanup stops the recursively discovered tree to a stable fixed point before kill/reap, including a detached process forked after an earlier stopped-root snapshot. An external `/proc` inspection failure remains an explicit failed containment proof even after best-effort known-root cleanup.
- Refactors that do not add capability must reduce maintained runtime code. No compatibility fallback remains after replacement tests pass.

## Library-first decisions

- Lifecycle coordinator: **no new FSM library**. `statig` and `smlang` provide async state/transition dispatch, but neither owns this service's transactional acquisition, reverse-order compensation, process/task joining, generation leases, or exact response-boundary commit. Adopting either would retain those domain effects while adding a second transition representation. The implementation therefore reuses the already locked `tokio` synchronization/task primitives plus one Rust state enum and exhaustive `match`; it is a consolidation of current code, not a new generic FSM runtime. The stage must remove the API/store/`DuplexRuntimeHandle` transition copies and finish with at least 100 fewer maintained production LOC across `api.rs`, `runtime_state.rs`, and `translation_runtime.rs`; otherwise the stage fails its architecture gate and is redesigned.
- Configuration validation: **reuse `serde` plus existing typed domain enums; no generic validation crate**. `serde` owns shape, enum, required-field, and unknown-field rejection. The remaining rules depend on cross-field direction/acoustic constraints and the live provider/model/voice capability snapshot inside one control transaction; `garde` or `validator` would still require custom callbacks and would duplicate rather than remove that owner. One pure domain admission function replaces scattered API/UI/provider checks, and its stage must delete more handwritten validation branches than it adds.
- HTTP schema/client: **adopt maintained libraries instead of a custom registry**. Pin compatible `utoipa` 5.x and `utoipa-axum` 0.2.x so the same typed route registration emits OpenAPI 3.1, and pin `openapi-typescript` to generate the Tauri/web client types. `translator-schema-check` is a thin deterministic generate-and-diff wrapper, not another schema model. The migration deletes the manual HTTP DTO portion of `apps/translator-ui/src/uiModel.ts` and any duplicate route/schema fixtures in the same stage; generated output is not counted as maintained handwritten runtime code. Net handwritten production LOC across the owned Rust API and TypeScript DTO surface must decrease.
- Every stage records before/after files and `git diff --numstat`; an adopted library is accepted only when obsolete custom code is deleted in that stage. Dependency lock/SCA/license gates remain mandatory.

## Serialized implementation order

1. **A — deterministic trust:** exact full-suite/collection gates, bounded SCA, baseline defect reproducers, and validation/publication entrypoint scaffolding; no product-behavior claim yet.
2. **B1 — Python ownership:** `ProviderRegistry` leases, OpenAI resource/correlation guards, verified model leases, private sidecar-generation IPC, and one production execution interface.
3. **B2 — Rust authority, serialized:** `ControlApplication` + transactional `RuntimeSupervisor`, then `SelectedProviderAdmission`, `CloudEgressAdmission`, acoustic admission, direction fault scope, `IncomingRouteCoordinator`, `RoundTripApplication`/session, transactional audio mix, and user-service reconciliation hooks. These share lifecycle state and must not be edited in parallel.
4. **C — one cross-language policy migration:** canonical core mode/config/deadline types, protobuf/codegen projection, and every Python/eval consumer change together; delete all copied tables in the same stage so no compatibility fallback is needed.
5. **D — quality and observability:** semantic repair/oracles, provider-specific readiness projection, debug owners, hotplug reactions, and bounded metrics/evidence.
6. **E — public/install boundary:** migrate Axum routes to `utoipa`/`utoipa-axum`, generate the TypeScript client with pinned `openapi-typescript`, move Tauri to one daemon projection, then verify packaged systemd lifecycle and portable staged install/rollback/release workflow.
7. **F — release proof:** paired product comparison plus controlled ablation where possible, soak, round-trip, native app, real-app, and exact-SHA hosted release gates.

Every numbered close requires the top-level architect-auditor verdict, source gates, documentation refresh, quantitative code-surface delta, commit, and push before the next stage.
