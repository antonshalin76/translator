# Рабочий план: стабильный пользовательский Translator

Дата: 2026-10-17. Статус: В РАБОТЕ, не разрешение на стабильный релиз.
Ветка: `codex/product-recovery-20261017`; исходный коммит: `8e3c651` (R14).
Старый `main` (`9291e8b`) не является исходным кодом установленного preview.

## Цель и границы

Работающий длительный двусторонний RU/EN перевод, простой интерфейс и
проверенный облачный режим OpenAI. Сохранить локальный режим, безопасность
наушников, независимые направления, исходные настройки и возможность отката.
Не создавать новый AEC backend, универсальный supervisor или ещё один UI/API.
Ошибки нельзя скрывать состоянием «Запущен» или бесконечными перезапусками.

Один рабочий процесс: developer-ultimate с Ponytail full; история помогает
восстановить факты, crossreview проверяет план и конечный результат. Не повторять
неизменившиеся дорогие проверки. Проверять именно прогресс перевода под речью,
а не только существование процессов/аудиопотоков. Автоматические проверки;
ручная слуховая проверка не является условием закрытия.

## Владельцы и минимальная архитектура

Rust ControlApplication — состояние, согласие, команды и desired/effective mix;
direction runtime — прогресс/таймауты/завершение; audio — идентичность/ресурсы PCM;
Python provider — inference/сетевые сессии; UI — проекция и команды;
systemd/installer — секреты окружения, процессная группа и поставка.
Исправлять причину один раз у владельца. Не дублировать правила в UI/тестах.

  показал 400-ms пакеты звука и интервалы 359–690 ms; прежний 250-ms guard
  объявлял отсутствие данных, пока в bounded playback ещё оставался звук.
  Исправляется учёт реально принадлежащего utterance звука, без увеличения
  очереди и без отмены пределов сбора входа, cancellation и hot I/O.
  Измеренный промежуток 690 ms при 400-ms пакете означает до 290 ms без
  оставшегося медиа: после его исчерпания starvation guard выбран 500 ms
  вместо 250 ms. Это явный quality-first компромисс по данным, не рост очереди
  или бесконечное ожидание. Cancel ack остаётся 250 ms; input 12 s, first audio
  6 s, source-age validator и hot I/O 1 s не меняются. Проверяются как успех
  измеренной пакетной последовательности, так и отмена настоящего starvation.
- Решение по OpenAI: единственный кандидат для следующей интеграции —
  `gpt-realtime-2.1`, строгий перевод RU/EN, голос `marin`, manual EOU.
  На шести одинаковых зафиксированных синтетических входах все GA вызовы
  завершились с PCM; 1–2 s до первого звука после EOU. Dedicated модель
  добавила отсутствующую в источнике просьбу, подтверждённую текстом и аудио.
  У GA таких добавлений в этих шести случаях не обнаружено. Turbo ASR и
  отдельный gpt-transcribe поддерживают смысл, но есть disagreement отдельных
  распознавателей и один внешний ASR transport failure. Frozen буквальный
  oracle дал GA 2/6: два случая — пропущенные синоним/транслитерация, ещё два —

  Новых модельных поисков не требуется; дальше одна замена существующего
  протокола, причинные тесты и runtime gate. Старый R14/Git остаётся откатом,

### Облачный путь через VPN: текущая реализация 19 октября

Проверки новых моделей выполнены только на фиксированных синтетических WAV,
без физического микрофона и без изменения VPN, маршрутов или DNS ОС.
Текущий кандидат использует один HTTPS-путь: `gpt-transcribe` → `gpt-4.1` →
`gpt-4o-mini-tts`, голос `marin`. Старый WebSocket runtime и его зависимости
удалены, скрытого fallback нет. Сеть обслуживает закреплённый `aiohttp`:
DNS запрашивается только на VPN-интерфейсе, socket привязывается к нему до
connect; отсутствие интерфейса, изменение его identity, proxy или redirect
не разрешают обход. Ключ остаётся во внешнем защищённом окружении.

На исходных 12 записях фактический HTTPS transport получил PCM в 12 случаях;
независимая оценка ASR, MT и двух распознаваний выходного аудио дала
8 PASS / 4 UNCERTAIN, без подтверждённых FAIL. Неопределённость не считается
успехом. Первый PCM: 1,993–3,136 s; два случая превышают действующие 3 s.
Дополнительная проверка четырёх реальных ASR-текстов подтвердила пользу
общего правила озвучивания чисел словами, но не заменяет полный повторный
прогон цепочки и не исправляет задним числом исходный результат.

Новая реализация сохраняет бюджет первого ответа от EOU, отдельный bounded
progress после подтверждённой публикации PCM, отмену и cleanup. Текст и
неполный sample не продлевают ожидание аудио. Ошибка публикации остаётся
фатальной, валидное пустое распознавание становится локальным `no_speech`,
а новая естественная фраза не должна отменять уже обрабатываемую предыдущую.
Нормальная отмена задаётся явным `CancelUtterance`; очередь ограничена,
ожидание входит в исходный deadline, перегрузка не становится бесконечным
накоплением работы.

Это source-кандидат, не установленный стабильный релиз. Окончательные native
проверки, пакет, sustained duplex и безопасная установка учитываются отдельно
в приватном delivery receipt. Чек-боксы исходного плана не закрываются по
короткому model smoke. Действующие 3 s, 6 s, 12 s и 250 ms не увеличены.

### Охват и оставшиеся риски

Инвентаризированы runtime/контроль/IPC/аудио, model lifecycle/scheduler/provider
registry/gRPC, UI/Tauri, конфигурация/установка/пакет и тестовые runners. Это
архитектурный охват и аудит связанных путей, не заявление о ручном чтении каждой
строки каждого исторического benchmark. Устаревшие evidence не заменяют новые.

Исправления у владельцев: `translation_runtime.rs` — backpressure, fatal handling,
recovery receipts; `local/local_provider.py` — fatal retryability;
`__main__.py`/`process_sidecar.rs` — выбранный provider при bootstrap;
`control_application.rs`/`api.rs` — сериализованная смена provider/mode только
после Stop; `runtime_state.rs` — voice engine при переключении; UI/Tauri —
простая проекция состояния и подтверждённые команды; installer остаётся прежним.

Открыты: качество/непрерывность фактической OpenAI цепочки,
пакет/установка/откат, автоматическая оценка смысла чисел/имён/отрицаний. Успешный
provider smoke или native fixture не закрывает эти пункты. Новая модель не
объявляется лучшей по одному примеру; текущие ключи и реальные устройства не
подменяются тестовыми фактами. Стабильный релиз не разрешён этой записью.

Критерий sustained gate: 20 минут, не менее 60 завершений на направление,
живой счётчик записи PCM и независимый счётчик ненулевого аудио private sink.
Под повторяемой речью отсутствие прогресса более 20 s — FAIL; тишина проверяется
отдельно и не считается зависанием. Stop ограничен текущим 8-s runtime budget.
Изоляция: Pulse без физических карт, RAM 8 GiB, swap 256 MiB, два CPU, 256 tasks;
live cloud только синтетические фразы с жёсткими лимитами calls/input duration.
Ни этот тестовый acoustic seam, ни UI fixture не доказывают физическую AEC.

Для каждого крупного gate: команда, входной SHA/diff и lockfile fingerprint,
результат, путь к приватному логу, ограничения. Результаты старого R14 не
переносятся на изменённые пути. История через codex-thread-workflows неполна:
catalog для точных репозиториев пуст, packet исходного thread доступен лишь
частично; текущий код/установка и новые требования имеют приоритет.

План/исправления не доказывают AEC, абсолютную точность речи или закрытие
старого Task7. Проверки качества, устойчивости, UI и установки различаются.
